# S3j 固定差旅复制重提

本阶段只实现本人已驳回/已撤回差旅的复制修改后重提。新记录有独立 ID、编号、版本、审批实例；原申请、附件、决定、通知和快照保留。没有动态字段、模板配置或自定义流程逻辑。

## 使用流程

在本人已驳回/已撤回详情的“复制修改后重新提交”区域查询后续申请。没有后续记录时可“复制为新草稿”，确认框说明范围；取消不写入。复制成功后点击“编辑重提草稿”，核对日期/预算、修改内容并选择附件，再使用既有保存与提交流程。新草稿与新提交详情提供“查看原申请”；原详情提供已有后续记录入口。历史审批人和管理员没有复制权限或后续查询特权。

复制标题、出发地/目的地、日期、目的、同行人员、交通、精确预算和备注；自然日天数由数据库重新计算。新草稿 version=1、submittedAt=null，部门采用申请人当前有效部门。提交时重新验证完整字段/附件并按当前有效部门与审批人解析固定两级路径，生成新任务、快照、日志及待办通知，不沿用原审批决定。

附件策略：两份原件没有要求自动复制附件，本阶段复制表单内容，原附件仍只关联原申请；新草稿附件列表为空。确认框与编辑器明确提示重新上传。旧原件可通过原详情按权限查看/下载，新上传文件独立归属于新申请。没有跨申请共享可删除的附件元数据，不复制历史审批意见到可编辑表单。

## 重复请求和链关系

每个原申请至多保留一个直接后续申请，由数据库 UNIQUE(resubmission_of) 保证。并发复制在原申请行锁上串行；若已有后续，则返回其当前摘要而不重新复制、不覆盖已编辑内容、不自动提交。后续已提交后再从原申请复制也只返回该记录；若后续又驳回/撤回，从后续记录继续生成下一环。

未提交后续草稿可按原草稿规则删除，删除后再次明确复制可以创建新编号；因此这不是跨删除的永久幂等键机制。页面不会自动重放 POST。网络/5xx/冲突等失败暂停写入，提供 GET“核对复制结果”找回已有后续；原版本冲突需刷新整份原详情。导航时其他窗口可能删除或提交草稿，目标页仍重新读取并处理 404/409。

来源字段 resubmissionOf（数据库 resubmission_of）只由专用服务设置，普通新建/编辑 schema 拒绝客户端写入；数据库禁止改写来源，禁止自引用/跨申请人/非固定差旅/非驳回撤回来源，并限制源记录删除。来源 ID 本身不授予原正文权限，新审批人不能凭关联读取无权的旧申请；旧审批人也不会继承新申请权限。
