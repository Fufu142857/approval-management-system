# 分阶段开发计划

当前状态：S0、S1 和 S2 用户与组织功能已完成（S2a 数据库、S2b 身份接口、S2c Web 页面及浏览器验收、S2d 公共外观对齐）。S3a–S3e 固定差旅审批、本人通知与受控附件后端已完成；S3f 已接入差旅草稿/附件/提交和只读详情 Web 页面。S3g 已补全差旅各状态与待办/已办列表后端；S3h 已接入列表与审批/撤回页面；S3i 已接入通知页面与前台轮询；S3j 已实现差旅复制重提，S3 固定差旅闭环完成；S4a 已实现固定采购数据模型与草稿后端；S4b 已实现固定采购报价附件后端；S4c 已实现采购提交与提交后详情；下一轮 S4d 实现采购审批动作。Docker 运行验证仍待后续交付阶段。每轮默认推进一个可验收增量，不要求一天一个阶段；完成验证、提交并汇报后再进入后续轮次。新 Agent 先读 [STATUS.md](STATUS.md)。

三类固定流程使用固定业务配置，不提前实现可由管理员配置的动态模板解释器。必要的通用存储和审批执行可以复用；任何变更若开始涉及自定义字段/模板配置/版本发布规则，立即进入人工边界，不以“共用逻辑”为由提前代写。

S2 拆分为 S2a 数据库/迁移/初始化（已完成）、S2b 认证与管理权限后端（已完成）、S2c 页面接入和全流程验收（已完成）。S2b 的真实接口、权限与错误响应见 API.md；S2c 页面与可复现浏览器测试见 WEB_IDENTITY.md。S2a 使用本机独立 PostgreSQL 17 实测，未启用系统常驻服务。已提供 Compose 数据库配置，但本机尚无 Docker 引擎，Docker 运行验证仍未完成；不能把配置存在等同于部署通过。S8 验证完整系统最终部署。

S2d（已完成）在进入 S3 前纠正公共外观：按原型采用黑白灰、侧栏和内容顶栏布局，重跑身份浏览器验收。后续所有界面以 UI_GUIDELINES.md 与外层 Design.pdf 为依据；当前身份页没有独立原型，不能宣称逐像素一致。

S3a（已完成）提供固定差旅本人草稿后端，包含未完成表单保存、列表/详情、完整替换和版本化删除；天数、编号、身份由服务端确定。15 项新增数据库测试和 HTTP 重启验证作为证据。

S3b（已完成）提供固定提交与提交后详情。固定 v1 默认采用本部门负责人 → 全组织财务审批人，恰好一名有效候选且不得自审；缺失或歧义拒绝提交。单次事务保存路径/人员快照、首节点 pending 与后续 blocked、日志和首条通知。新增 15 项测试及生产 HTTP 重启验证。使用固定版本标识与不可变快照，未实现可配置规则解释器；S3c 再补审批动作，业务页面仍未完成。

S3c（已完成）提供固定差旅通过/驳回/撤回与顺序推进；14 项新增测试覆盖终态拒绝、必填驳回意见、并发审批/撤回、后续任务失效、日志/通知一致性、已办权限与详情一致性，生产 HTTP 验证三个终态及重启保留。

S3d（已完成）提供本人通知列表/详情/未读数/幂等已读，独立检查接收人与正文权限；原任务状态随当前流程变化，旧待办不自动获得操作权。12 项新增测试与生产 HTTP 重启验收通过。

S3e（已完成）提供受控差旅附件上传/列表/删除/预览下载；真实格式解析、10 MiB/件、9 件/50 MiB/申请、申请版本竞争、草稿删除补偿与提交冻结、私有文件存储和孤儿回收。16 项新增数据库/文件测试与生产 HTTP 重启验收通过。

S3f（已完成）接入差旅草稿分页/搜索、新建/编辑、日期/预算校验、附件上传/预览/下载/删除、草稿删除确认和提交确认，以及提交后的只读详情/节点/历史。保存与附件操作共用申请版本；冲突或不确定写入保留本地内容并停止重试。外观沿用第 7、8 页公共原型；没有独立差旅专图，不作逐像素一致承诺。PDF 使用本地 PDF.js 逐页渲染，不依赖浏览器插件。页面与验收见 WEB_TRAVEL.md。

S3g（已完成）提供固定差旅本人全状态申请和当前用户待办/已办列表后端，支持类型、申请状态、上海日历日期与标题/编号关键词筛选分页；已办按本人 approved/rejected 任务统计，不包含取消任务。单 SQL 快照返回条目/计数/当前节点；007 补充查询索引。15 项专项与生产 HTTP 验收见开发日志。

S3h（已完成）接入全状态申请/待办/已办列表页面，以及已有通过/驳回/撤回 API 的确认与冲突反馈；已查看 Design 对应公共原型并执行真实浏览器验收，页面/边界见 WEB_TRAVEL_APPROVAL.md。

S3i（已完成）接入本人通知列表/详情、侧栏未读数、显式已读与受权限控制的申请跳转；页面可见时每 30 秒读取，隐藏/离页/退出时取消对应读取，失败提示与旧数据区分。说明见 WEB_NOTIFICATIONS.md。

S3j（已完成）提供固定差旅已驳回/已撤回申请复制重提：新草稿、新编号、不可变来源，同源并发复用唯一后续；保留原历史/附件，新草稿需重新上传附件并按当前部门与审批人员重新提交。界面与验证见 WEB_TRAVEL_RESUBMISSION.md。

S4a（已完成）实现固定采购数据模型与本人草稿 CRUD、明细/报价稳定行 ID 与重排、精确行金额和总额、权限/版本/事务验证。草稿保存允许不完整；比价、单一来源、预算和线上截图的完整性留在提交阶段强校验，不能把字段可保存当作提交规则已实现。

S4b（已完成）提供同单报价附件的上传/整单列表/预览下载/删除、整单配额、版本与文件补偿。删除有附件的报价需先显式删除附件；整单删除事务后回收文件。仅允许本人草稿，未提前授权采购提交后读取。

S4c（已完成）固定采购提交与提交后详情：完整验证明细、预算、比价/单一来源/选择理由和线上截图，核文件完整性并保存实际审批路径/人员快照，按真实资源权限开放提交后正文/附件。用户已确认固定路径“本部门负责人 → 企业负责人”，版本 fixed-purchase-v1。

S4d（下一步）固定采购审批动作：当前实际节点通过/驳回、本人撤回，按冻结人员推进并原子写状态/任务/日志/通知；补版本、并发、失效人员与正文/附件历史权限验收。之后拆分采购列表、页面与重提，报销及统计继续分步，不提前实现自定义模板或动态规则。
