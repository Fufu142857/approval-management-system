# S4l 固定报销提交与提交后读取

本阶段实现已保存报销草稿的提交、固定审批人员快照、提交后详情/票据授权及首节点通知；S4o已补草稿/票据页面，提交详情Web与重提尚未实现。接口见 API.md，S4m 已补通过/驳回/撤回，见 REIMBURSEMENT_ACTIONS.md。

## 提交条件

只接收最新 version，不能用提交请求替换正文、身份、金额或审批人。服务在本人申请排他锁内重新读已保存字段及票据，重新核对所有关联源是本人已批准的差旅/采购；无关联时要求独立报销说明。标题、报销说明、至少一条完整费用为必填；每条费用须有固定类型、有效日期、用途与正金额，备注可空。支持三条以上不代表强制所有单据凑满三条。

每条明细默认须有本行至少一份票据，其他行的票据不能替代；缺票须显式 noReceipt=true 且填写原因。只填原因但不选例外仍拒绝；已选例外即使另有文件也保留标记/原因，不静默改写用户声明。所有已上传文件（包括无票行附加文件）都检查归属、号码、整单配额及原文件大小/SHA-256，缺失或损坏拒绝提交。票据号码不是税务真伪校验，不做OCR或按内容/号码跨单去重。

金额先按既有 schema 重新规范化，再使用整数分重新合计并与NUMERIC结果核对，冻结精确总额。无票项目的id/原因及票据id/itemId/号码/类型/大小/摘要进入快照，不含私有存储键；财务界面的突出显示留待后续UI阶段。

## 固定人员与一致性

fixed-reimbursement-v1：申请人当前有效部门恰有一名有效 department_head → 全组织恰有一名有效 finance_approver；人员部门也须有效。候选缺失或多名拒绝，不按排序任意选人；任何节点为申请人本人拒绝。同一非申请人可兼任两步，仍生成两条有序任务。

同事务更新 pending/version+1/当前部门/提交时间，新增不可变实例快照、首节点pending/财务blocked、提交日志和首节点通知。失败整体回滚，重复/并发只能成功一次。快照保留当时申请人姓名/部门、具体人员、规则、费用总额/例外/票据证据和必要的关联来源摘要；提交后组织角色变化不会重算旧路径。

锁顺序为组织/身份/部门 → 报销申请排他锁 → UUID排序的来源共享锁；提交不删除或新建文件，与上传/删除/正文保存共用申请版本及锁。提交后正文、费用、链接和票据写入口关闭，已有数据库触发器继续冻结费用/关联/票据；实例及日志不可变。无新迁移，仍为014。

## 读取权限和关联摘要

本人及曾激活过任务的实际审批人员可以通过 reimbursement-applications 路径读取；未激活的未来财务节点、管理员、新任负责人和其他人没有额外权限。详情/文件先持申请共享锁，再重新鉴权，避免等待期间权限变化；草稿路径依旧只允许本人draft。通知目标API可指向报销，读取通知不替代正文授权；目前通知Web不生成尚不存在的报销页面链接。

提交后详情只展示提交时冻结的关联来源摘要（含必要差旅行程/采购金额）。审批报销不授予源单全文、历史、附件权限；源申请须按其自己的权限读取，不能沿关联扩大访问。后续源单异常变化不改写报销提交时的证据。正文返回{application,workflow,tasks,logs}，来源摘要在application.linkedApplications与workflow.routeSnapshot.linkedApplications中保持提交时内容。
