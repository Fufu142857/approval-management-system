# 固定采购草稿与报价附件页面（S4f）

本增量接入已有草稿和报价附件 API，不改变服务端契约或数据库迁移。采购提交、提交后只读详情、审批/撤回、全状态/待办/已办页面及复制重提尚未接入，不能据本页声明采购 Web 闭环已完成。固定流程仍为用户确认的部门负责人 → 企业负责人；动态模板与字段不在本增量内。

## 入口与代码

“我的申请”中的“采购草稿”进入 `/purchase/drafts`，支持本人草稿标题/编号搜索、分页、刷新和继续填写；`/purchase/new` 新建，`/purchase/drafts/:id` 编辑。所有页面通过 requireBusinessPageUser，详情/文件继续由 API 检查本人权限；管理员没有额外正文权限。

- `src/components/purchase-editor.tsx`：固定采购字段、明细/报价行、选择及单一来源、版本和附件交互。
- `src/components/purchase-drafts-panel.tsx`：草稿列表入口。
- `src/lib/purchase-display.ts`：去掉派生字段的保存输入，以及先校验规范化再计算的精确金额预览。
- `src/components/travel-common.tsx`：既有弹窗和附件读取组件；AttachmentItems 新增可选 resource，只允许 travel-applications（默认）或 purchase-drafts。鉴权仍在服务端，不是动态附件字段引擎。
- `src/app/(workspace)/purchase/`：服务端页面认证、UUID 校验和身份显示；浏览器不选择申请人或部门。

## 填写与保存

基础信息包含标题、只读当前部门/申请人、只读首次保存日期（上海日历）、采购原因、期望到货日期、所属项目及预算。明细表可增删名称/规格/数量/单位/单价；报价表可增删供应商/日期/金额，并展开编辑链接、线上标记和报价依据。供应商选择最多一家；单一来源开关不自动删掉已有报价或说明。备注在底部展开填写。

草稿允许未填完。数量最多三位、金额两位，输入校验与服务端共享 purchaseDraftSchema；预览先规范化输入，再用整数逐行 half-up 到分后求和。缺项/键入中的无效数值显示待补全，不当零；超过合计上限明确提示，保存仍严格校验。每行上限失败显示未知金额并在保存时标错。预算可以为零，已填数量、单价、报价须大于零。提交必填和完整比价规则仍由已存在的提交 API 强校验，保存成功不代表可以提交。

保存 PUT 为全量替换，保留服务器返回的行 ID，只给新行省略 ID；不发送编号、身份、派生金额等字段。删除行保存后生效，删除当前选中报价后选择清空。草稿整单删除需确认，连同报价附件删除；删除附件也有单独确认。

## 报价附件

先保存草稿及至少一条报价，再在底部明确选择附件所属报价。新加但未保存的报价不能上传；每次一个 JPEG/PNG/PDF，单件 10 MiB、整单 9 件/50 MiB。拖拽和文件选择均使用同一入口；真实内容及配额由服务端再验证。未保存的供应商名称只是当前表单显示，绑定始终使用已保存报价 ID。

附件按报价分组，图片通过已鉴权内容接口读取为临时对象 URL；PDF 使用既有本地 PDF.js 分页绘制；下载保留文件名与原始字节。文件不进入 public。含附件报价的删除按钮不可用；先显式删除该报价全部附件，再删报价并保存。服务端 QUOTE_HAS_ATTACHMENTS 仍为最终保护，跨窗口新增附件不会被覆盖删除。

上传/删除只更新申请版本和文件列表，**不保存当前表单文字**。文字保存与附件操作共享 version，成功后继续使用新版本。首次创建和普通保存规范化表单；其余操作保留未保存输入。

## 冲突、失败与离开

- 保存、上传及删除期间同步锁住写操作，避免双击并发；校验在禁用表单前完成，能定位错误字段。
- 冲突、非草稿、资源缺失/行变化，或者网络超时/断连/5xx 等不确定结果，保留本地输入并暂停写入。不会自动重试 POST/PUT/DELETE，也不会自动提交申请。
- “新窗口查看服务器记录”读取当前草稿；首次创建响应丢失时打开草稿列表核对新编号。已被其他客户端提交后草稿路径拒绝读取，本阶段尚无提交后页面，应通过现有已授权 API 核对，下一阶段补详情入口。
- 手动“丢弃本地修改并重新加载”需确认，丢弃当前输入，重新获取正文和附件；两个 GET 的版本不一致时不能进入编辑，需重读。
- 页内普通链接与刷新/关闭提示未保存内容；浏览器历史前进/后退不保证拦截。整页离开、登录失效重定向仍可能丢失本地内容，不提供本地持久化或自动合并。
- 文件读取失败提示在该附件组中；它是只读请求，可手动再试。普通输入/格式错误可修正再保存，不视为提交成功。

## 外观依据与已知范围

已查看外层设计第 8 页原型，沿用黑白灰外壳、两张可编辑表格、下方并排的采购选择/单一来源卡片，以及底部虚线附件区、保存/提交按钮。桌面四列基础信息；手机基础字段和选择卡片单列，表格仅容器内横向滚动。删除和上传使用同一单色图标系统。

相对静态原型，保留真实业务所需的期望日期/项目/预算、报价依据编辑、报价绑定选择、配额/冲突/错误说明及阶段不可用提示；附件支持格式按既有安全接口为 JPEG/PNG/PDF，不支持原型示例中的 Word。草稿表格没有独立专图。原型结构已作为实现依据，但不宣称整页逐像素相同。原件、提取图和浏览器截图均不提交。
