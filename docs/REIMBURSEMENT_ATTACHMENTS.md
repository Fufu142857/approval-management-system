# S4k 固定报销票据后端

本阶段完成本人报销草稿的票据上传、列表、受控预览下载、单件删除及含票据明细/整单删除保护。没有报销页面或 OCR，S4l已补提交/详情，S4m已补审批动作（REIMBURSEMENT_ACTIONS.md）；真实 HTTP 契约在 API.md。

每个附件记录使用服务端 UUID，通过 reimbursement_item_id 绑定本申请已保存费用行。复合外键防止跨单关联，单值外键与不可改绑触发器保证一个票据记录不会同时用于两条明细。禁止从客户端传 attachmentId 复用；一条明细可有多份票据。相同号码/文件再次上传仍是新记录，本阶段不承诺内容识别或跨单重复报销预警。

票据号码随上传可选填写，去边缘空白、限100字符、无控制/格式字符；不是金额或税务真实性验证。上传人/时间/文件名/类型/大小/摘要由服务端保存，列表返回 itemId/receiptNumber，私有存储键不暴露。记录不可原位修改，号码或归属错误须显式删旧记录再上传。

单件10 MiB、整单9件/50 MiB，所有费用共同计数；沿用已有 JPEG/PNG/PDF 实际内容校验与私有存储。无票标记与票据可以在未完成草稿中暂时并存，附件操作不自动修改正文。草稿允许100条费用不代表可上传100份票据；实际文件配额独立受控。S4l提交接口已逐行校验票据或明确无票理由。

上传/删除均更新同一申请 version，不能保存未提交的表单文字。PUT 费用明细时保留行ID即可保留文件，省略含文件行返回 ITEM_HAS_ATTACHMENTS，先显式删除该行全部附件再保存。整单删除先提交数据库事务，成功后回收文件；错误或不确定提交结果只依据持久引用回收，不能直接 unlink。

新迁移014扩展既有attachments，不修改001–013；新增报销明细复合外键、索引、可空明细绑定和默认空号码，旧差旅/采购附件不改归属。触发器限制本人报销草稿上传/删除、禁止改绑或改元数据、拒绝其他类型使用报销字段。组织→存储72004→申请锁序沿用现有协议；列表/内容读取持申请共享锁，GC独占存储锁。

专项 tests/reimbursement-attachments.test.ts 覆盖三种真实格式/原字节、号码、权限/跨业务、配额/版本、重排/显式删除、数据库约束、故障回滚/孤儿回收、缺失/损坏、并发及重连/迁移。生产 HTTP 追加实际 multipart、费用保护、三种格式重启后的原字节与删除。最终执行结果见 STATUS.md；本阶段没有界面改动或截图结论。

S4l已实现：固定报销提交校验、固定“部门负责人 → 财务审批人”人员快照、提交后详情及票据读取授权。S4m已补通过/驳回/本人撤回与历史权限；列表、页面、重提及统计继续拆分。到 S5 仍停止整个项目代码修改并交棒给用户独立实现自定义模块。
