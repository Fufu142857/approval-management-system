# S4j 固定报销草稿后端

本阶段只有数据模型与 HTTP API，没有报销页面、复制重提或统计；审批动作已由S4m补齐，见REIMBURSEMENT_ACTIONS.md；S4l已补提交完整校验和提交后读取，见REIMBURSEMENT_SUBMISSION.md。票据上传/读取/删除已由S4k补齐，见REIMBURSEMENT_ATTACHMENTS.md。入口/参数/类型见 API.md。S4k 已接同单费用明细的票据附件，不一次完成整条报销流程。

## 固定字段与金额

报销头保存标题、说明、独立报销说明、备注；身份/部门/编号/时间由服务端确定。费用类型为 transport（交通）、lodging（住宿）、meals（餐饮）、office（办公）、other（其他）五类固定值，允许草稿未选；明细有日期、用途、金额、无票标记和原因。最多100条，支持稳定行ID编辑/重排、删省略行、新行新ID。

金额使用字符串和 NUMERIC(14,2)，合计由服务端计算，客户端不能传总额。已填金额须大于零、最多两位小数，按整数分校验总上限；零行或有缺金额行则总额null。无票说明和独立说明可先空，保存不意味着提交条件满足。票据号码属于后续每个票据记录，不把多个票据压成一个费用行号码。

## 关联与权限

application_links 对应设计的“已批准采购/差旅 → 新报销”，与重提来源 resubmission_of 是不同含义。允许最多20个本人已批来源，或空数组作为待填写/独立报销。候选接口只查当前本人已批准两类单，分页/类型/字面关键词筛选；保存时重新检查，不能依赖先前候选查询。

本人草稿详情附必要来源摘要，差旅含行程/自然日天数/预算，采购含预算/精确总额；不返回源附件/审批正文。服务端逐次检查所有权与状态，源单关联不给管理员/财务/其他审批人增加权限。关联不改源正文、时间、版本、任务、历史和附件；取消关联/删除报销仅删链接。允许同源对应多份报销，本阶段没有累计已报销额限制或跨单重复票据检测。

## 并发与数据库

013 新增 reimbursement_requests / reimbursement_items / application_links；applications.type 新增固定 reimbursement，旧迁移与差旅/采购来源保护不改，报销重提尚未开放。明细顺序唯一约束可延迟检查以允许重排；链接复合主键防重复，FK禁止悬空或误删来源。触发器限制报销正文/明细/链接只在草稿修改，禁止改绑行及报销类型/申请人；插入链接强制同本人、approved、travel/purchase。

服务先组织/身份/部门锁，再报销申请锁；需要来源时按UUID排序取共享锁。所有写入同事务，失败回滚主表、费用与链接。详情持报销共享锁跨所有查询，避免混合版本；列表计数与条目同SQL快照。PUT/DELETE 必须带最新version，后到并发写失败，客户端未来接入不能自动重放不确定请求。

## 测试和后续边界

新增业务/数据库测试覆盖未完成保存、三条与五类费用/精度上限、无票标记、严格输入/Origin/体积、稳定行与完整替换、所有权/非终态/跨业务关联拒绝、来源摘要/不变性、分页、并发与版本上限、数据库约束、故障回滚和多查询锁一致性。生产 HTTP 验收加入 CRUD、候选、多来源/精确总额、重排和 Web 重启后保留，结果以 STATUS.md 为准。

S4k 已实现票据号码与文件元数据、同单明细归属、受控上传/读取/删除及含票据明细的删除保护。完整提交须重查有效费用、关联或独立理由、每行票据或明确无票原因；财务突出显示和后续流程/UI 另拆阶段。到 S5 依然停止整个项目代码修改并交棒。
