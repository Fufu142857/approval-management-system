S4a 采购接口 /api/purchase-drafts 只支持本人草稿，和 travel API 相互隔离；最多 100 明细/20 报价，行 ID 由服务端生成、PUT 沿用本单 ID 才能保留。PUT 是完整替换，省略数组会删除旧行；新行不传 ID。数量三位/单价两位，行金额 half-up 到分再求和，任何行金额缺失或零行则总额 null。所有金额为字符串；预算可为零，已填数量/单价/报价必须为正。最多选一家供应商，S4c 已在提交阶段验证完整比价、单一来源说明、预算及线上截图；草稿接口仍允许未完成数据。采购 POST/PUT JSON 256 KiB，其他接口默认 16 KiB。草稿读取持申请共享锁、写入持排他锁，草稿保存不产生审批/通知；S4b 已扩展报价附件关联、整单删除文件补偿；省略含附件报价会返回 QUOTE_HAS_ATTACHMENTS，必须先显式删附件。

S4c 新增 POST /api/purchase-drafts/:id/submit（严格 version）、GET /api/purchase-applications/:id 及该前缀的附件列表/content。提交核已保存明细/报价/原文件，不接受客户端正文替换；非最低价理由、单一来源说明和报价来源条件见 API.md。报价允许金额或 basis 明细；任何金额未知时最低价结果为 null，不能当零。预算须覆盖预计总额及有金额的拟选报价。线上报价须同报价 JPEG/PNG 及 HTTP(S) 链接，不做截图语义识别或电商抓取。

采购 fixed-purchase-v1 为本部门唯一有效 department_head → 全组织唯一有效 company_head；这是用户在 S4c 明确选择，差旅路径不变。提交冻结实际人员、预算/精确总额/选择及单一来源说明、比价结果/附件摘要；同事务 pending/version+1、两任务、提交日志、首待办通知。审批人缺失/多名/自审拒绝并回滚。采购申请/附件提交后仅本人或曾激活任务的实际人员可读；未来 blocked 企业负责人、财务、管理员无额外权限。草稿读取路径仍仅本人 draft，不扩大权限。读取先申请共享锁后授权，S4d 状态写持同一申请排他锁。

S4d 新增 POST /api/purchase-applications/:id/tasks/:taskId/decision（version、approve/reject、opinion）及 POST /api/purchase-applications/:id/withdraw（version、opinion）。只有当前实际任务人员可审批，本人不能自审；本人 pending 可在任一节点撤回。approve 激活冻结的下一人员，末节点通过终结；reject 必填理由并取消后续任务；withdraw 取消未办，保留已办与历史。旧版本/终态/旧任务重试拒绝，失败先重新读取，不自动重放。

下一快照人员停用或部门无效时批准整体回滚，不换成新任负责人，仍可驳回或本人撤回。状态/任务/日志/通知在一个申请排他锁事务里提交，不改正文、报价、金额、提交时间或快照。撤回通知本人及曾激活人员、按人去重；从未激活的企业节点没有通知或正文/文件权限。审批人与申请人的终态历史权限已验证，通知目标/任务状态反映当前状态。详情、附件读等动作提交后重新授权，完整接口与错误码见 API.md。

编号取舍已落定：首次创建草稿分配非空唯一 APP-序号，提交沿用；回滚/删除可产生空号。日期采用上海日历日期、首尾均计入，不记录日内时刻。草稿可缺字段，保存通过不代表提交校验通过；PUT 是完整替换，省略字段会清空，必须携带 version，详见 API.md。

固定差旅 v1 默认采用“本部门唯一有效负责人 → 全组织唯一有效财务审批人”，不按金额分支；候选不足/多名或本人审批一律拒绝，由管理员调整授权。设计未写死差旅第二级角色，S3b 已询问但未收到用户选择，按预先说明的建议值实施，不记作用户确认。已提交人员快照不可改写；同一非申请人可分别承担两步。S3c 沿用此固定规则；下一快照审批人停用/部门无效时拒绝当前批准并回滚，不换人或跳过。通知已覆盖各状态事件和本人查询/已读 API；S3i 已接入通知页面、前台轮询与受控跳转。没有动态模板、版本发布或可配置规则解释器。

列表说明：差旅/采购各有独立的全状态本人申请和任务接口。申请列表只含本人申请，按创建时间；任务 pending 仅当前实际待办、handled 仅本人已通过/驳回的任务，分别按激活/完成时间。取消任务不计已办，同一人处理两步保留两条任务。from/to 按上海日历日包含首尾，status 始终筛选申请当前状态；各接口的 type 分别只允许 travel 或 purchase。总数/分页/当前节点/申请版本同一 SQL 快照，跨请求可能变化；未知/重复参数返回 400。当前节点和已提交申请人姓名来自提交快照，列表不授予额外审批权。差旅类型/服务在 src/lib/travel-lists.ts、src/server/travel-lists.ts；采购对应 purchase-lists.ts，见 API.md。采购摘要另含 budgetLimit/totalAmount（精确字符串或 null）及 singleSource；零条或缺金额明细的草稿合计为 null，完整草稿舍入零是 "0.00"。不返回报价/附件/完整理由。草稿专用列表仍按更新时间，和全状态创建时间列表不同。

S3h 操作 UI：仅本人 pending 申请可撤回，当前实际任务人员且非本人可通过/驳回；确认框显示编号、标题、节点和意见。驳回必填，取消保留意见。成功后重新读取详情与附件；冲突/资源变化/不确定写入暂停写入并保留意见，手动重新读取后按新状态开放操作，不自动重放或自动批准下一节点。当前页面重新读取保留意见，整页刷新/离开会丢弃。

审批与撤回必须携带最新申请 version；审批还须携带实际 taskId，旧任务不能借新版本推进下一节点。已激活过任务的人员在有效身份下可以查历史，未激活即取消的未来节点没有正文权限。申请详情共享行锁与审批排他行锁保持多查询一致；后续状态写入不得绕过此锁。

S3j 差旅与 S4i 采购来源 resubmissionOf 不可改写，仅本人 rejected/withdrawn 可以 GET/POST resubmission；组织锁后锁原申请，并发复制复用同一个直接后续，不改原版本/时间/历史。删除未提交后续可重建；后续已提交则保留链，再次终态从后续继续。新草稿当前部门、version=1、新编号，附件为空，提交重新解析当前人员；采购明细/报价为新行 ID，线上报价需重新上传同报价图片，保留精确金额、单一来源和未知报价语义；来源关联不传递正文权限。失败不自动重放，先 GET 核对，见 API.md。

S3i 通知读取不自动标记已读，需显式点击。可见页面每次读取完成后间隔 30 秒再查询，隐藏取消 GET，恢复立即读取；离开通知页停止列表/详情读取，侧栏计数在有效登录工作区继续。退出开始即暂停，401/403 停止对应轮询；计数 403 显示不可用而不反复重定向。失败保留旧数据并明确提示，已读失败只回查 GET、不自动重放 POST。不是后台推送。

通知仅凭接收人身份查询/标记；正文目标另行按 S3c 权限检查。通知标题/类别是历史事件，target.status/task.status 是当前状态；不能按旧待办标题执行审批。列表 total 按筛选统计，unreadCount 是本人全量未读数。POST 已读只收 {}，重复和并发调用保留首次时间。

附件只允许本人草稿上传/删除，每次递增申请 version；提交前验证文件完整性，提交后冻结。列表/下载与正文授权一致，管理员和未来 blocked 节点无特权。限额按 10 MiB/件、9 件与 50 MiB/申请，详情见 API.md。默认私有目录 uploads/attachments（可用 ATTACHMENT_STORAGE_DIR 配置），不能放 public；异常回收用 `pnpm attachments:gc`，必须与当前数据库配套。上传/删除锁顺序为组织 → 存储 72004 共享锁 → 申请；回收独占 72004 后确认数据库引用，不能直接删不确定提交结果对应文件。测试已隔离文件目录，不得改为开发 uploads。
