# S3f 固定差旅 Web 页面

本增量接入 S3a–S3e 已有 API，没有新增业务接口、迁移、审批动作或动态表单。左侧“我的申请”当前进入差旅草稿；S3g 已提供全状态申请与待办/已办列表 API，但这些列表页面、审批/撤回页面和通知页面仍待后续增量。

## 页面与使用

| 路径                     | 已实现行为                                                                            |
| ------------------------ | ------------------------------------------------------------------------------------- |
| /travel/drafts           | 本人差旅草稿；按标题/编号搜索、每页 10 条、刷新、空态、加载/错误/重试、新建和继续填写 |
| /travel/new              | 固定差旅表单；保存不完整草稿，校验完整后提交；首次保存后地址替换为草稿详情            |
| /travel/drafts/:id       | 继续编辑、保存、附件上传/预览/下载/删除、确认删除草稿、确认提交                       |
| /travel/applications/:id | 已提交差旅只读详情：正文、状态、人员快照、顺序节点、日志、附件与手动刷新              |

所有页面由 requireBusinessPageUser 重新验证登录、active 状态及有效部门，不能只靠共享 layout 或隐藏导航。资源读取与变更继续逐请求由已有 API 鉴权。管理员没有其他用户的草稿/正文/附件权限。未提交草稿访问已提交详情会提示无权/不存在，已提交记录打开旧编辑地址会提示状态变化并提供详情入口。

表单字段固定为标题、目的、出发地/目的地、起止日期、交通、同行人员、预算和备注；申请人/部门来自认证身份只读展示。星号表示提交必填，保存草稿允许缺失。预算使用十进制字符串；自然日含首尾的前端提示使用日历日期计算，最终值由服务端生成。保存和提交共用后端 schema，不提供动态字段配置。

首次保存之前不会自动创建空草稿，保存后才能添加附件。一次上传一件，支持选择文件与拖放；客户端提示扩展名/单件大小/数量/总量限制，真实格式与权限仍由服务端验证。附件上传/删除后的申请 version 回写编辑器；附件操作不隐式保存其他文字修改。删除草稿和附件均需确认，取消不发写请求。

提交先完整校验，再确认；若当前表单有修改则保存完整字段，再按保存后的版本提交。成功进入只读详情，不自动扩展工作台；目前可保存详情地址以便再次访问。已提交申请列表的页面接入留待后续阶段，不把仅草稿列表称为完整“我的申请”。

## 并发、失败与附件预览

- 操作期间禁用写按钮和字段，并用同步互斥引用阻止重复点击。版本冲突、非草稿、版本上限或网络/服务器错误导致写入结果不确定时，保留当前输入、禁用继续写入，提供新窗口核对与确认后重新加载；不会自动重放 POST/PUT/DELETE。新建请求响应丢失时先去草稿列表核对，避免重复创建。
- 普通校验/格式错误和审批人无法确定会显示原因，允许改正后再次操作。保存成功但提交失败时保留已保存草稿。重新加载会清除本地未保存修改，按钮明确确认；普通页内链接离开和刷新/关闭也提示未保存修改。浏览器历史前进/后退不提供自定义拦截保证，重要修改应先保存。
- 列表查询通过 useResource 取消旧请求并匹配查询键，筛选切页不会展示旧结果。草稿与附件、详情与附件分开读取，版本不一致时要求重新加载，不拼接不同版本。
- 图片/PDF 先通过同源受控内容 API 读取原字节；失败显示错误、不打开预览。图片在模态框中显示，PDF 通过本地 PDF.js worker 解析并逐页绘制到 canvas，支持上一页/下一页；不执行文档 JavaScript、动态表单或链接动作。每页绘制尺寸最长边限制 1600 像素，失败可下载原件。临时对象 URL 在关闭/卸载时回收，下载 URL 延迟回收；不把原件写入 localStorage。
- 对话框使用原生 dialog（焦点限制、Escape、关闭和取消）；错误定位字段并提供 aria-invalid/描述文本。详情状态与日志同时用文字显示，操作结果不单靠颜色表达。

## 外观依据与验收范围

已渲染查看外层设计第 7、8 页：公共侧栏、四格标志、内容顶栏、黑白灰、白卡片、分区标题、输入框、虚线附件区和保存/提交按钮均沿用原型。第 10 页仅文字列出差旅/详情功能，没有独立差旅、草稿列表或详情设计图，因此本阶段是按公共原型规范实现固定差旅页面，不能声称存在可逐像素比对的差旅专图。保留文字需求中的日期、目的和附件等字段，不复制采购特有区域或原型假数据。

桌面与 390×844 响应式 Web 通过本机 Chrome 实测，截图位于忽略的 tmp/screenshots/travel-*.png；原型渲染仅在本机临时目录，不进入 Git。列表宽表在容器滚动，手机表单/详情为单列。Safari、Firefox、手机真机和小程序不在当前验收结论内。

## 代码与测试入口

- src/components/travel-drafts-panel.tsx：草稿列表；travel-editor.tsx：固定字段与版本化操作；travel-detail.tsx：提交后的只读快照/状态/历史。
- src/components/travel-common.tsx：差旅确认/预览对话框与附件读取；src/lib/travel-display.ts：固定差旅 HTTP 展示类型、中文状态、上海时间和大小显示。
- src/components/pdf-preview.tsx：本地 PDF.js 逐页绘制；scripts/prepare-pdf.mjs 在 dev/build 前从锁定的 pdfjs-dist 6.4.299 准备 worker、字体、CMap、WASM、ICC 和许可证到忽略的 public/vendor/pdfjs/版本号，不依赖 CDN，不复制用户附件。部署应保留构建生成的这些公开库资源；Node 最低 22.13，建议 24 LTS。
- src/server/page-auth.ts：requireBusinessPageUser；src/lib/api-client.ts：JSON 和 FormData 共用请求、错误 code/fieldErrors；既有身份调用保持兼容。
- tests/e2e/travel.spec.ts：五组新增 Chrome 场景，真实数据库与生产 Web；结合原身份五组共十组。测试库额外为 roster_20/21 分配固定审批角色，测试数据不进入开发库。

运行顺序：pnpm build，然后 E2E_BROWSER_CHANNEL=chrome pnpm test:e2e。测试会重置独立 TEST_DATABASE_URL，不能与 pnpm test 或 pnpm test:http 并行。浏览器用例覆盖真实提交/附件路径；模拟响应丢失、附件不可用、无审批人仅用于检查页面反馈，后端真实失败规则由既有数据库测试覆盖。实际执行结果与修正记录见 DEVELOPMENT_LOG.md。

PDF 渲染使用 [Mozilla 官方示例](https://mozilla.github.io/pdf.js/examples/) 与 [API 参数说明](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html)，仅渲染既有附件内容，不涉及人工动态表单模块。
