# S4h 采购列表与审批操作页面

本阶段接入已有 S4d/S4e 固定采购 API，无新增 HTTP 契约、数据库迁移或自定义模板能力。S4h 时数据库为 011，当前 S4i 为 012。S4i 已另行接入采购复制重提，见 WEB_PURCHASE_RESUBMISSION.md。

## 入口与筛选

| 路径                       | 用途                              |
| -------------------------- | --------------------------------- |
| /purchase/applications     | 本人全状态采购申请                |
| /purchase/drafts           | 原有本人采购草稿管理              |
| /purchase/tasks            | 当前用户实际待办                  |
| /purchase/tasks/handled    | 本人已通过/驳回任务               |
| /purchase/applications/:id | 冻结正文、附件与权限内的审批/撤回 |

从差旅列表的采购入口或申请类型选择框进入，采购草稿导航与全部申请互通。采购页面的侧栏“我的申请/我的待办”保持采购上下文；差旅和采购可以在内部导航或类型选择框互相切换。切换业务类型进入对应模式的默认查询，重置该模式筛选，不混合金额与条目；尚无跨类型合并列表。

本人全状态列表按创建时间、待办按接收（激活）时间、已办按处理时间筛选；上海日历日期包含首尾，关键词匹配标题/编号。支持申请当前状态、分页，默认每页 10 条；筛选与页码存入 URL，刷新和浏览历史可恢复。查询重置到第一页；非法/重复/未知查询参数提供重置入口。列表显示加载、无结果、越界页、读取失败及重试；切换期间禁用筛选，旧请求取消且不能覆盖新条件。

摘要显示申请编号/类型、标题/快照申请人、申请当前状态、预算与精确预计金额、当前审批人及相应时间；单一来源明确标记。金额 null 显示未填或待补全，不当零。已办额外显示节点及其已通过/驳回结果：一个节点已通过不等于申请最终通过，取消不计已办，同人处理两节点会保留两条记录。草稿进入编辑器，其他记录进入详情核对；表格不提供直接审批。

## 操作、权限与失败恢复

服务端页面通过 requireBusinessPageUser 获取当前身份 ID，API 继续独立鉴权。只有本人 pending 可撤回；只有本次详情中已激活、前序均通过的实际 pending 节点人员且非本人能审批。管理员/财务/未来 blocked 节点没有额外权限，终态和已办历史只读。正文与附件版本/状态不同或读取失败时不显示操作面板。

通过、驳回、撤回先确认，显示编号/标题、实际节点与意见；驳回必填理由，取消或 Escape 保留意见且不发 POST。沿用 purchaseDecisionSchema/purchaseWithdrawalSchema。每次发送当前申请 version；审批同时使用实际 taskId，不根据角色推算未来节点。写入期间互斥，禁用操作、刷新和附件按钮；原生对话框约束焦点，关闭/刷新窗口提示正在处理。

成功后清空本次意见，显示结果并重新读取正文及附件；同一人负责两级时仍需再次明确确认，不自动推进下一节点。409、404、超时/断连或 5xx 暂停写入、保留意见，手动“重新读取详情”核对真实状态后才恢复合适操作，不自动重放 POST。成功后读取失败也应从详情重试核对。会话/账号失效沿用现有登录/账户反馈。

意见在当前详情组件中保存，手动重新读取保留；整页刷新、离开或会话失效跳转可能丢失，不提供跨会话意见草稿。关闭客户端等待不代表撤销服务器写入。后端仍负责锁、版本/身份、下一冻结人员可用性，以及状态/任务/日志/通知事务一致性。

- purchase-list-page.tsx：业务身份及 URL 校验；三个 page.tsx 选择固定列表模式。
- purchase-list-panel.tsx：真实采购摘要/筛选/分页与导航，复用既有类型和公共黑白灰表格。

- account-shell.tsx、travel-list-panel.tsx、purchase-drafts-panel.tsx：既有侧栏/内部导航与类型切换，无动态表单或规则解释器。
