# S3h 差旅列表与审批页面

本阶段只接入 S3c/S3g 已有 API，没有新增业务接口、数据库迁移、动态模板或可配置流程。通知页面/轮询后由 S3i 接入（WEB_NOTIFICATIONS.md）；复制重提仍待后续增量；当前数据库为 007。

## 入口与查询

| 路径                     | 功能                                                    |
| ------------------------ | ------------------------------------------------------- |
| /travel/applications     | 本人全状态差旅申请；侧栏“我的申请”入口                  |
| /travel/drafts           | 保留原草稿管理，由“全部申请 / 草稿管理”导航互通         |
| /travel/tasks            | 当前用户实际待办；侧栏“我的待办”入口                    |
| /travel/tasks/handled    | 已办任务；从“待办事项 / 已办事项”导航进入               |
| /travel/applications/:id | 原详情扩展为受权限控制的审批/撤回页面；正文和附件仍只读 |

列表页面逐页调用 requireBusinessPageUser 检查业务身份，资源 API 继续独立鉴权。当前类型只有差旅，类型控件明确显示且不可切换到未实现业务。支持申请状态、日期、标题/编号关键词筛选，默认每页 10 项；共享 schema 处理日期/分页/白名单，错误 URL 提供重置入口。有效查询条件和页码写入 URL，刷新/历史导航可恢复；提交筛选重置到第一页，重置清空筛选。页面跳转期间禁用筛选控件并显示切换提示，避免重置尚未完成时输入被后续重载覆盖。请求取消与查询键匹配沿用 useResource，显示加载、空结果、越界页、错误与重试状态。

日期使用北京时间，包含首尾日。本人列表按创建时间，待办按接收（激活）时间，已办按处理时间；页面标签明确区分。申请状态是当前状态，已办节点结果单独显示，不能把已通过节点误认为申请已最终通过。同人双节点仍按任务显示，取消任务不计为已办。点击草稿进入原编辑器，其他记录进入既有详情；不在表格直接盲批申请。

## 操作与失败处理

服务端页面把当前认证用户 ID 传给详情组件；只有申请本人在 pending 时能看到撤回，只有当前实际 pending 任务人员且非本人能看到通过/驳回。终态和无关历史人员只读，管理员无额外正文或审批权。UI 隐藏按钮只是展示规则，服务端继续验证本人、taskId、version、前序任务和账号状态。

通过、驳回、撤回都先展示确认框，包含编号、标题、本次节点（审批时）、意见和影响说明；取消或 Escape 不发写请求并保留意见。驳回必须有理由，沿用 travelDecisionSchema/travelWithdrawalSchema；校验失败定位意见字段。写入期间禁用操作和详情刷新，原生 dialog 限制焦点，互斥引用阻止重复点击；关闭/刷新窗口时提示正在处理。

写入发送本次读取的申请 version 和实际任务 ID，不从未来节点推断。成功提示结果并重新读取详情与附件，避免沿用旧版本；不会自动批准下一节点，同一人负责两步也需再次明确确认。正文与附件版本不一致时先提示刷新，不展示操作按钮。

网络/超时、5xx、409 或资源不存在意味着需要核对状态，暂停继续写入，保留意见并提供“重新读取详情”。不会自动重放 POST；重新读取成功后按最新权限显示操作，若终态或已无待办则隐藏按钮。重新读取保留当前页面内意见；整页刷新、离开页面会丢弃未提交意见，不提供跨会话意见存储。会话失效跳转登录；账号/部门无效沿用已有账户反馈。成功后回读失败时使用详情重试入口核对真实状态。
