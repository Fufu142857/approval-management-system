# 界面外观与验收约束

用户要求界面外观与外层 `../Design.pdf` 一致。该文档是视觉依据；开发前必须查看对应原型，不能用另一套配色、品牌或布局代替。原件不随公开仓库发布，迁移时由用户私下提供，原型图片和浏览器截图也不提交。

## 参考范围

- 第 7 页：整体黑白灰视觉及工作台原型，确定 Web 公共外壳、导航、标题、搜索、用户菜单、卡片与表格语言。
- 第 8 页：采购表单原型，后续固定业务表单按其分组、密度、按钮与表格逐项核对。
- 第 11–12 页：小程序原型与移动适配要求，进入对应阶段再按原件验收；当前响应式 Web 不是小程序实现。
- 其他具体页面在对应阶段查看原件。自定义模板原型属于用户独立实现范围，不因视觉对齐而提前实现。

目前文档没有为登录、注册、个人资料、用户管理与授权审计提供各自独立原型。S2d 将这些页面放入相同的公共视觉框架，属于沿用原型规范；不能把它们称为已有完整原型的逐像素复刻。原型中的示例姓名、记录、统计数字不作为业务数据，也不能据此扩展作业范围。

## 当前公共实现

| 部分         | 代码位置与约定                                                                               |
| ------------ | -------------------------------------------------------------------------------------------- |
| Web 外壳     | `src/components/account-shell.tsx`；桌面左侧导航、右侧内容顶栏，标题在顶栏，用户入口在右上角 |
| 标志与图标   | `src/components/icons.tsx`；四个黑色圆角方格标志、单色导航与控件图标；不引入独立彩色品牌     |
| 颜色与排版   | `src/app/globals.css`；正文近黑、辅助文字灰色、浅灰背景、白卡片、轻分隔线                    |
| 桌面结构     | 外壳最大宽 1388px，侧栏 240px，顶栏 112px；较窄屏侧栏 200px，手机改为顶部导航与单列内容      |
| 控件         | 黑色主按钮、白色次按钮、浅灰表头、灰色状态胶囊；状态同时使用文字与符号，错误同时提供明确文字 |
| 固定身份表单 | `auth-form.tsx`、`access-editor.tsx`；沿用公共输入框、分组、确认与取消样式，不生成动态表单   |
| 登录页       | `src/app/(auth)/layout.tsx`；公共标志与居中白色卡片，身份页无独立设计图，保持同一视觉语言    |

上述数值是当前实现基线，并非把 PDF 展示画布的外部留白硬套到所有屏幕。后续有具体页面原型时，仍须以原件和真实浏览器对照调整。不要为了风格统一而删除错误说明、键盘焦点、字段标签、权限保护或真实数据。

管理入口在侧栏“管理后台”，内部使用“用户管理 / 操作审计”导航；个人信息和退出在右上角用户菜单。“我的申请”当前开放差旅草稿列表，新建/编辑与提交详情沿用公共框架；工作台、待办、通知及全局搜索尚未实现，仍显示不可用入口。后续阶段完成实际能力后再启用。

## 每次界面改动的检查

1. 查看原件中对应页面，确认公共框架和页面内容的区别，不把原型展示内容当作已实现业务。
2. 对照布局、层级、间距、字体、图标、配色、控件和状态；不能只以“功能正常”代替外观验收。
3. 在真实浏览器检查桌面和手机视口，确认表格容器滚动、页面无水平溢出，验证受影响的交互。
4. 在 STATUS 和开发日志记录检查范围、未覆盖部分与后续工作。原始设计图和验收截图保留本地，公开仓库只保存代码与文字记录。

S2d 已纠正 S2c 的自定配色与布局；现有身份页的功能浏览器用例仍在 `tests/e2e/identity.spec.ts`。后续工作台和业务页面尚未实现，因此本检查点不代表全部设计页面已完成或已逐像素验收。
