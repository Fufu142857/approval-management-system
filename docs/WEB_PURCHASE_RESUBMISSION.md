# S4i 固定采购复制重提

本人已驳回/已撤回采购详情 /purchase/applications/:id 显示“复制修改后重新提交”。点击“复制为新草稿”先确认申请编号/标题、复制范围与附件规则，取消或 Escape 不写入；确认只发送当前原单 version。草稿/审批中/已通过及其他人员无此入口；API 独立授权。

复制采购基本字段、明细、报价、拟选供应商及单一来源说明，生成新申请编号、新明细/报价 ID；原单正文、历史、审批意见与原附件保留。新草稿不复制任何报价附件，必须重新核对日期、预算、比价、报价依据和供应商，并为线上报价重新上传同报价 JPEG/PNG。新单编辑/提交走既有固定采购流程，重新解析当前部门负责人和企业负责人。

成功后显示“编辑重提草稿”；后续已提交则显示“查看后续申请”。新草稿和提交后详情向本人显示“查看原申请”，新旧正文和附件分别鉴权。原审批人不能凭来源关系读取新申请，新审批人也不能因此读原单；这不是跨单授权功能。

同源并发返回同一个直接后续，不覆盖已有修改。删除尚未提交的后续草稿后可重新复制；后续已提交不可覆盖，后续再次驳回/撤回从它继续。服务器拒绝旧版本，客户端任何复制失败或结果未知都停写，保留当前页面并提示先“核对复制结果”；该按钮仅 GET，可找回已创建草稿。版本冲突须刷新整份详情再确认；不自动重试 POST。请求期间锁定复制、刷新和附件按钮；整页关闭/刷新有处理中提示。

后续关系查询提供加载、失败与恢复提示。复制成功后若读取失败，应再次核对而不是盲目创建。取消浏览器等待不代表服务器没有完成写入。没有跨会话草稿意见或自动提交。

## 代码和数据库

- src/components/purchase-resubmission-panel.tsx：采购专用确认、关系查询及恢复面板，使用既有 TravelDialog/Notice 和黑白灰控件。
- purchase-detail.tsx / purchase-editor.tsx：入口权限、来源链接和附件重传提示；不改变采购字段和附件编辑布局。
- src/server/purchase-resubmission.ts、purchase-resubmission-handlers.ts 与对应 API route：事务及 HTTP 边界，契约见 API.md。
- 012_purchase_resubmission.sql：扩展既有不可变来源关联到固定采购，保持差旅兼容；无动态模板/字段解释器。
