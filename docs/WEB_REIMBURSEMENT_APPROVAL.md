# S4q 固定报销列表与审批操作页面

本阶段使用既有 S4m/S4n 接口，无新增 HTTP 契约或数据库迁移，仍为015。提交与冻结正文/票据见 WEB_REIMBURSEMENT_SUBMISSION.md。S4r已另行接入报销复制重提（WEB_REIMBURSEMENT_RESUBMISSION.md），统计继续分步；到 S5 停止整个项目代码修改并交棒。

## 入口与查询

| 路径                            | 用途                            |
| ------------------------------- | ------------------------------- |
| /reimbursement/applications     | 本人全状态报销申请              |
| /reimbursement/drafts           | 本人草稿管理                    |
| /reimbursement/tasks            | 当前实际待办                    |
| /reimbursement/tasks/handled    | 本人已通过/驳回的节点           |
| /reimbursement/applications/:id | 冻结详情、票据与权限内审批/撤回 |

报销侧栏保持报销上下文。差旅、采购、报销列表通过内部链接及固定类型下拉切换，同模式进入目标默认查询，不合并业务条目或金额。既有差旅/采购的报销草稿快捷入口保留，报销草稿与全部申请互通。

全状态按创建时间、待办按激活时间、已办按完成时间筛选；日期按北京时间含首尾，关键词匹配标题/编号，状态筛选申请当前状态。默认每页10条，筛选及分页保存在URL，查询回第一页，刷新/历史可恢复。页面只允许page/pageSize/type/status/keyword/from/to；重复、未知或非法参数提示重置，state由路由决定。加载、无结果、越界空页、读取失败/重试和切换中状态均明确显示，旧请求不能覆盖新查询。

摘要显示编号/类型、标题/申请人/部门、申请状态、精确金额、显式无票数、当前审批人与对应时间。金额字符串直接展示，null为“待补全”，不当零；无票数不是缺附件数，也不代表提交校验通过。已办另显示实际节点及其结果，申请终态与节点结果独立；取消不计已办，同人两步分别列项。草稿进入编辑，其余进入详情核对，表格没有直接审批按钮。

## 操作及恢复

页面以requireBusinessPageUser取得viewerId，API继续独立授权。本人pending只开放撤回；非申请人、实际pending节点已激活且前序均通过才开放审批。管理员、未激活财务和无关人员没有额外权限，终态只读；正文与票据version/status不一致或任一读取失败时不显示正文和操作。

通过/驳回/撤回先确认，展示申请编号/标题、实际节点和意见。复用reimbursementDecisionSchema/reimbursementWithdrawalSchema，驳回必填；取消或Escape不发POST并保留意见。动作只发送最新详情version及实际taskId，不按角色猜节点；写入互斥，禁用操作、刷新及附件按钮，关闭/刷新窗口提示处理中。冻结来源及票据内容继续只读，无源全文权限扩展。

成功后清空意见并重读正文/票据；同一人负责部门与财务仍需再次明确确认。409、404、网络/超时、5xx暂停写入并保留意见，必须手动“重新读取详情”核对真实结果后再操作，不自动重试POST或批准下一步。下一冻结财务失效时后端批准整体回滚，不改派，刷新后仍可驳回或由本人撤回。会话失效按既有身份流程跳转。

意见只存在当前详情组件，手动回读保留；整页刷新/离开/会话失效可能丢失，不提供跨会话草稿。关闭客户端等待不代表撤销服务器写入。状态/任务/日志/通知原子性、角色变化不改冻结人员和历史权限继续由既有后端保证。
